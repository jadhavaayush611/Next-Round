# API Design Specifications

All frontend-backend communication is done via RESTful APIs over HTTPS. This document details routing conventions, authentication headers, schema mappings, and responses.

---

## 1. Request URL Structure

All API endpoint paths are prefixed with the API version:
```
/api/v1
```

* **Resource Naming**: Use plural nouns for resources (e.g. `/api/v1/resumes` instead of `/api/v1/resume`).
* **Trailing Slashes**: Do not append trailing slashes to endpoint paths (e.g., use `/api/v1/users` instead of `/api/v1/users/`).

---

## 2. Authentication & Authorization

All authenticated endpoints are secured using JSON Web Tokens (JWT) inside standard HTTP headers:

```http
Authorization: Bearer <JWT_ACCESS_TOKEN>
```

* **Issuance**: Tokens are generated by the `/api/v1/auth/login` endpoint.
* **Expiration**: Tokens are configured to expire after 60 minutes.
* **Payload**: The JWT payload contains the user's UUID in the `sub` claim.

---

## 3. Reference Endpoints

### 3.1 Authentication & Registration (`/auth`)

#### `POST /auth/register`
Creates a new candidate account.
* **Body (JSON)**:
  ```json
  {
    "email": "student@college.edu",
    "password": "securepassword",
    "name": "Candidate Name",
    "college": "Institute Name",
    "graduation_year": 2027,
    "branch": "Computer Science",
    "cgpa": 8.5,
    "target_role": "Backend Developer"
  }
  ```
* **Response (201 Created)**:
  ```json
  {
    "id": "a0eebc99-9c0b-4ef8-bb6d-6bb9bd380a11",
    "email": "student@college.edu",
    "name": "Candidate Name",
    "college": "Institute Name",
    "graduation_year": 2027,
    "branch": "Computer Science",
    "cgpa": 8.5,
    "target_role": "Backend Developer",
    "created_at": "2026-07-19T22:20:00Z"
  }
  ```

#### `POST /auth/login`
Authenticates a user and returns an access token.
* **Body (Form-Data)**:
  - `username`: Email string.
  - `password`: Password string.
* **Response (200 OK)**:
  ```json
  {
    "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "token_type": "bearer"
  }
  ```

---

### 3.2 User Profile (`/users`)

#### `GET /users/me`
Retrieves the logged-in user's profile details.
* **Headers**: `Authorization: Bearer <token>`
* **Response (200 OK)**: User profile JSON object.

#### `PUT /users/me`
Modifies the logged-in user's profile information.
* **Headers**: `Authorization: Bearer <token>`
* **Body (JSON)**: Partial dictionary of fields to update.
* **Response (200 OK)**: Updated user profile JSON object.

---

## 4. HTTP Status Codes

We use HTTP status codes to communicate call results:

| Status Code | Name | Description |
| :--- | :--- | :--- |
| **`200 OK`** | Request Succeeded | The request was processed and returned results. |
| **`201 Created`**| Resource Created | Registration or file upload succeeded. |
| **`400 Bad Request`**| Validation Failed | Missing payload items, invalid formats, or duplicate emails. |
| **`401 Unauthorized`**| Credentials Missing| Expired, invalid, or missing JWT headers. |
| **`403 Forbidden`**| Permission Denied | Attempting to mutate data owned by other users. |
| **`404 Not Found`**| Resource Missing | Target user, resume, or roadmap does not exist. |
| **`500 Internal`**| Server Error | Unexpected database failures or internal python exceptions. |
